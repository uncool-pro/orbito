# Prototype scope

**Role:** business analyst. **Part of:** `process-rapid-prototype`. **Comes before:** user flows and wireframes for the chosen paths.

A rapid prototype answers one question for the client: *is this what we are building?* The scope decides which smallest set of screens makes the idea clear.

## How
- Read all the context there is: transcripts of calls, offers for the client, functional requirements, notes, the brief. Summarise in 3–5 sentences what the product is, for whom, and what makes it valuable.
- List the candidate happy paths (main tasks that end with the person getting value).
- **Pick one, at most two**, that show the concept best: the task that carries the core value, and if needed a second one that shows something the client is unsure about. Say why each was picked and what was left out.
- For each chosen path: the steps, the screens it needs (aim for 3–7), the key content per screen, and the assumptions you made because the input was silent.
- Write it as one short epic with a story per path (`user-stories`, light version: story and 2–3 criteria) so the prototype has a trace.
- If the input is too thin to choose (no idea who the user is or what the core value is), ask the person 1–2 questions instead of guessing.

Bring the proposal to the person and get a yes before anything is built.
